# Contributing

Thank you for your interest in contributing. Contributions, suggestions, and constructive feedback are welcome.

## Before You Start

1. Check the existing issues and pull requests to avoid duplicating work.
2. For a significant change, open an issue first so the direction can be discussed.
3. Keep pull requests focused on one improvement whenever possible.

## Development Workflow

1. Fork the repository and create a branch from `main`.
2. Use a descriptive branch name, such as `feature/add-search` or `fix/task-filter`.
3. Make small, focused commits with clear messages.
4. Update the documentation when behavior or setup changes.
5. Test your changes locally before opening a pull request.

## Pull Requests

Please include:

- A clear summary of the change
- The reason for the change
- Testing steps and results
- Screenshots or recordings for user-interface changes
- Any known limitations or follow-up work

Pull requests should be respectful, reviewable, and free of unrelated formatting changes. Maintainers may request revisions before merging.

## Issues and Bug Reports

When reporting a bug, include:

- A clear title and reproduction steps
- Expected and actual behavior
- Relevant environment details
- Logs or screenshots with secrets removed

For feature requests, describe the problem being solved and the proposed user benefit.

## Code and Documentation Style

- Prefer clear, maintainable code over clever shortcuts.
- Follow the conventions already used in the repository.
- Keep documentation accurate and easy to follow.
- Never commit passwords, API keys, private tokens, or personal data.

## Security

Please do not report security vulnerabilities in a public issue. Contact the maintainer privately through GitHub so the issue can be handled responsibly.
